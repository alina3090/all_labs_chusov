Это программа для быстрого вычисления остатка от деления очень больших чисел на компьютере с несколькими процессорными ядрами.

## Проблема

нужно разделить число из тысячи цифр на какое-то обычное число, скажем, на 13. 
Компьютер хранит большие числа как массив кусков по 64 бита. 
Обычное деление "столбиком" делается последовательно — сначала берём старший разряд, делим, берём остаток, 
добавляем следующий разряд и так далее. Это медленно, потому что нельзя просто взять и разделить работу между несколькими ядрами 
— каждый шаг зависит от предыдущего.

## Решение

Программа использует хитрый математический трюк. 
Оказывается, если разбить большое число на части, то каждую часть можно обработать отдельно, а потом собрать результат.

Сначала большое число режется на куски — по одному на каждое процессорное ядро. 
Например, если у тебя 4 ядра и число из 1000 цифр, каждое ядро получит по 250 цифр.

Каждое ядро считает остаток от своего куска независимо от других. 
Но здесь есть загвоздка — кусок, который обрабатывает второе ядро, на самом деле находится не в начале числа, а где-то посередине.
Значит, его результат нужно умножить на специальный коэффициент, чтобы учесть его реальную позицию в большом числе.

После того как все ядра посчитали свои локальные остатки, программа объединяет их. 
Делается это по схеме дерева: сначала ядро 0 складывает свой результат с результатом ядра 1, 
ядро 2 — с ядром 3, потом ядро 0 складывает общий результат с результатом ядра 2. 
Так за логарифмическое время от числа ядер получаем финальный ответ.

## Технические сложности

При делении больших чисел очень легко получить переполнение. 
Если перемножить два 64-битных числа, результат может не влезть в 64 бита. Программа решает это по-разному в зависимости от компилятора. 
Если это GCC на 64-битной системе, используется тип unsigned __int128 — он вмещает результат умножения двух 64-битных чисел. 
Если компилятор не поддерживает 128-битные числа, программа разбивает каждое число на две половинки по 32 бита, 
перемножает их по формуле, как в школе учили, и аккуратно собирает результат обратно, проверяя переполнение на каждом шаге.

Все потоки синхронизируются через барьер — это такая штука, где потоки ждут друг друга. 
Когда все доходят до барьера, они продолжают работу дальше. Это нужно на этапе объединения результатов, 
чтобы никто не начал складывать раньше, чем другие закончат вычисления.

## Что измеряет программа

Программа сначала проверяет, что всё считается правильно — 
для этого есть набор из десяти тестов с известными ответами. Потом запускает серию экспериментов: 
сначала одно ядро, потом два, три и так далее до максимума. 
Для каждого количества ядер замеряется время работы и выводится таблица — 
сколько миллисекунд заняло вычисление и во сколько раз быстрее это по сравнению с одним ядром. 
Это позволяет увидеть, насколько хорошо алгоритм масштабируется — идеально было бы увидеть, что при удвоении числа ядер время уменьшается вдвое.

| Столбец          | Значение                                                          |
| ---------------- | ----------------------------------------------------------------- |
| **T**            | Количество потоков (ядер процессора)                              |
| **Value**        | Вычисленный остаток (одинаковый для всех — проверка корректности) |
| **Duration, ms** | Время вычисления в миллисекундах                                  |
| **Acceleration** | Ускорение относительно 1 потока (Time₁ / Timeₜ)                   |
